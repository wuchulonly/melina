# 命名与维护约定

项目在包名、CLI、源码与部署产物中统一使用 Melina。

| 范围 | 命名 |
| --- | --- |
| SDK 与核心类型 | `Melina`、`MelinaError`、`MelinaEvent`、`MelinaContainers` |
| 函数与局部实例 | `melinaRuntime`、`melina` |
| 配置与环境变量 | `MELINA_*` |
| 容器内项目目录 | `/melina/*`，临时进程状态为 `/run/melina` |
| 领域镜像 | `localhost/melina-<领域>:<内容哈希>` |
| 交付分支 | `melina/<runId>` |

测试文件按行为或组件命名，例如 `coordinator.test.ts`、`run-page.test.tsx`。测试标题描述触发条件和预期行为，不使用会话号或审查批次。

源码注释说明当前职责、不变量、边界条件和必要原因。已删除机制的变更过程、讨论日期、用户确认和补丁编号留在 Git 历史或仓库外的归档记录中。当前格式以 schema 为准，历史格式和已删除协议不保留兼容实现。

主分支保留源码、测试、当前文档及构建所需的锁文件和来源信息。旧仓库快照、迁移清单和过程笔记保存在仓库外；构建日志、前端构建目录、测试结果及 Python 缓存不提交。

求解会话统一称为 Bet 0，由 Explorer 持续执行并自动压缩上下文；初始副本和摘要接力使用同一工具与提示词。`continuation` 标记接力：得分只更新验收水位和来源的 `toolCallsAtAccept`，经过 `momentumToolCalls` 次调用仍无新验收才评估独立入口，允许零分叉。接力 Bet 的 `task`、`baseWatermark` 标记起点；满额时新水位可替换同任务中无近期产出的旧接力，保留来源、初始会话和仍有得分动量的路线。待执行计划在生成、存档、替换和恢复时检查水位，过期计划关闭未启动的 Bet 并释放快照保护。启动补齐及 `disabledBet0Copies` 仅按初始副本计数。配置解析后的 `bet0.models` 数组决定初始路数，`copies` 只在档位模型解析时生效。持久化协议的 `kind: 'direct'` 与 `mode: 'direct'` 保留为存储标识。

归档、来源清单和已经发布的镜像标签保留原名，以便核对来源。外部主机的现有账户、状态目录和 systemd/VPN 服务名也按实际部署填写；这些标识不作为新源码的命名依据。

升级使用新命名的版本时，SDK 调用同步改用 `Melina*`，并用 `pnpm images` 重建配套镜像。在已有任务结束后切换服务和容器，避免运行中的旧容器与新路径混用。持久化的历史事件、观测正文与归档不做字符串替换。
