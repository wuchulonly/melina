# 观察者提交协议

模型更新方向结论；宿主负责证据身份、尝试历史、读取预算和验收来源。工具声明与执行校验使用同一份冻结窗口。

- 结论更新必须提供 `evidence`。短码从冻结目录选择，数据库仍保存原始记录 ID。短码来自不可变事件身份，不允许按邻号修正。
- 输入整理只补齐该方向 `result` 中明确引用、且在冻结窗口内的执行依据；显式 `evidence: []` 保持原义。同列表有有效执行依据时可剥离未知引用并告警；只有错号时退回。正文、提示和其他分支观测不会被猜成执行证据。
- 只改变方向生命周期时提交 `{id, retired}`，保留原结论、依据和全部尝试。归档不等于失败；未知方向不能只提交生命周期更新。
- 每轮默认最多三次 `observation_context`，每次可批量查询。预算耗尽后从模型工具列表移除读取工具；提交失败后至多开放一次纠错补查。调用者可通过宿主 `contextLimit` 为需要完整分页的读取设置预算。硬截止和单次字节上限仍生效。
- `telemetry` 省略表示没有新报告，`null` 明确撤回，对象表示新报告。`watch.noted` 不复制上版报告；`runProgress` 投影保留最后一次报告的 `reportedAt`、`basedOnSeq` 与证据。后续观察窗口提供这份报告的原版次和证据水位，供模型更新或明确撤回；重新采样、更新地图都不能刷新旧报告的时间。
- `tension` 只能为空数组或两句原话；单句明确报错，不静默丢弃。单句疑点使用方向的 `doubt`。
- flag 的 `receipt` 始终指向本分支的宿主验收依据，`dependsOn` 仅记录本分支的关联方向。`source.runId/branchId/observationId/directionIds` 记录实际产出分支及方向，由宿主根据原始观测和产出分支的历史生成，读取不超过冻结边界。消费者不需要重提回执，也不会被记为产出者；没有对应方向时仍能追溯到回执和已知原始观测。

模型只看到本分支可引用的回执，原始来源 ID 不作为跨分支执行证据暴露。历史事件不回写，新版本及只读进度投影使用上述语义。
