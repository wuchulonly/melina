# CTF / Benchmark 运行时扩展

通用运行时默认不加载此扩展，也不根据目标里的文件名或 `domain: ctf` 自动启用平台规则。

命令行部署显式设置：

```sh
MELINA_RUNTIME_EXTENSION=./extensions/ctf/entry.ts pnpm melina serve
```

SDK 使用 `melinaRuntime({ extensions: [ctfExtension] })`，其中 `ctfExtension` 从 `extensions/ctf/entry.ts` 默认导入。扩展需由使用方显式启用。

扩展通过通用钩子提供：

- `prompts`：按当前 Run 的 `goal.domain === 'ctf'` 注入 [CTF 执行约束](execution-policy.md)，供解题 Explorer 与旁观者使用；目标或完成标准同时约定两份宿主反馈文件时，再注入 [TSec 宿主协议](tsec-policy.md)。Scoper 和终局挑版不追加，普通 CTF 不追加平台细则，非 CTF 任务不注入。角色补充支持静态字符串或 `({ run }) => string | undefined`，每次组装现读任务，不跨 Run 缓存领域判断。
- `checkTool`：按当前领域与本分支 WatchNote 检查命令策略；`sh` 等待工具名额后会再检查。
- `beforeTool`：首次环境交互前等待或补齐同一 Run 的宿主只读反馈文件。
- `beforeClose`：检查最终候选的平台验收状态；返回 `{ again }` 保持会话继续，不消耗收尾返修次数。
- `watcherInput`：采集宿主进度与独立 HTTP 日志，通过当前分支的 sink 统一脱敏、去重和存档，再冻结观察窗口。

TSec 的候选采集、平台反馈、实例重建和跨代次复核、续跑细则统一维护在 [TSec 宿主协议](tsec-policy.md)。赛事调度器的新建和续跑目标只保留题面、授权范围、状态文件入口、提示与调度安排、完成条件；托管任务说明也只引用该协议，避免长篇操作手册进入 Scoper、终局挑版和接力目标。目标已有完整的当前策略时扩展不重复注入；只有同名标题或旧版条款时仍追加当前策略，防止漏掉更新。历史目标、已生成的约束和消息不自动重写。没有加载扩展的本地或其他部署须按上文显式配置入口。

候选证据与完成标准的对应校验仍由核心负责。宿主验收只读取视图，不使用 workspace 中可改写的进度副本。命令分类改自原实现，许可见 `steer.LICENSE`。nuclei 通过 `sh` 仅放行显式单个本地 YAML 模板路径及有限的请求、输出、限速参数；标签、目录、URL、工作流、配置文件、多个模板和未识别参数均拒绝。命令识别是静态启发式，不检查容器内文件类型、模板内容或隐式工具配置，也不解释任意脚本；执行前仍须阅读模板，确认产品指纹与目标范围。托管环境另要求 `-ni` 并禁止外部回连及联网搜索题解，见其领域说明，这两条不施加于所有本地 CTF。

执行约束是持续给模型看的行为要求；命令拦截独立执行，登录并发与退避、操作必要性和目标范围不由此启发式检查器强制计量。各 direct 分支的后置工具按本分支旁观者地图放行。托管入口已经加载扩展，更新由新启动的运行时和调度器读取。扩展复用 Melina 的事件触发接力和统一候选交付接口，不依赖旧 Director 或脑暴角色。
