# CTF 执行约束

## 目标范围

- Web／CVE 题只访问题目给定的当前地址和端口，不扩扫网络；内网题可在题目明确授权的网段内推进，不因发现新主机而自行扩大范围。部署环境若进一步限定目标，按该范围执行。

## 解题执行与建议

以下要求适用于所有解题分支及接力分支，旁观者提出的建议也须遵守。

- Nmap 默认按无特权模式运行；TCP 探测使用 `--unprivileged -sT`，已知目标可加 `-Pn -n`。`-sV` 不授予原始套接字权限。`sh` 默认开启 `pipefail`；权限不足、超时或工具报错须修正后复验，不能当作有效阴性探测。
- 先读题面、附件与已知事实，明确目标和输入材料，再按证据选择分析或验证方法。优先复用页面、状态接口和响应已暴露的标识、凭据与上下文；代理或转发接口受限时，检查地址表示、参数透传与跨层请求解析边界。工具保留原始证据，旁观者维护覆盖台账；只补会改变后续判断的关键发现、重大意外和必要交接，不逐条抄写流水。
- 需要初始探测时只做轻量收集。目录探查自选少量路径存入 `wordlists/paths.txt`，dirsearch 必须显式指定 `-w wordlists/paths.txt`；同一轮单层、双段与反向组合合计不超过 200 条候选路径，循环请求也遵守此限额，不通过拆批扩大预算。授权范围内每批端口少于 80 个，不用 `nmap -p-`。不使用 ffuf、gobuster、feroxbuster、dirb、dirbuster、wfuzz、nikto（帮助和版本查询也会拦截）。漏洞验证根据已确认的产品指纹选 PoC，先读请求内容再定向复现；nuclei 只允许 `-t` 显式指定单个本地 `.yaml`／`.yml` 模板文件，禁止标签、模板目录、URL 模板、工作流和全库扫描，不用配置文件或其他选择器扩大模板集合。
- Web 路由发现先从当前题面、附件、页面引用、前端脚本、接口描述和响应中提取路径、资源名与操作名，优先验证已暴露的入口；线索不足时用少量通用根路径建立初步覆盖。单层未命中时，在剩余预算内补查语义相关的 `/命名空间/动作` 或 `/资源/操作`；按当前目标的命名习惯选择组合，存在顺序线索时再考虑反向，不做完整笛卡尔积。父路径不存在不能排除子路由；候选去重、扣除已查覆盖，并为不同结构预留预算。
- 路由探查先以不存在路径的响应建立对照，比较状态码、响应体、长度与重定向位置，识别统一错误页；认证拒绝或方法不匹配只作为待验证线索。按响应判断是否需要比较尾斜杠形式和不同访问条件。发现可读资源、新接口、参数或访问条件后先跟进验证，不要求路径直接返回 flag 才算有信息；未测试的结构与条件保留未知，不把一次小表阴性扩大为整个路由方向无效。
- 同一目标、相同条件下，一轮目录探查或某类小字典验证没有新增信息后，记录覆盖范围和结果，转向其他有证据支持的方向；新线索、目标或条件变化时可复验，不反复盲扫。旁观者当前地图标记 `forbid: ["dirbust"]` 时暂停目录探查，撤销后再继续。
- 禁止大规模弱口令爆破、rockyou 和无依据的超大字典。登录只用轻量小字典或已有情报支持的有限候选，不压垮服务。定向候选使用 `spray_users.txt`、`spray_passwords.txt`、`spray_creds.txt` 或 `loot.json`；SQLi／LFI 小词表使用 `wordlists/sqli.txt`、`wordlists/sqli_login.txt`、`wordlists/lfi.txt`。这些名称用于识别定向验证，不能靠改名包装泛化字典。direct 分支的 hashcat、john、hydra、medusa、patator、jwt_tool、jwt-cracker 和普通 `wordlists/passwords.txt`、`wordlists/usernames.txt`、`wordlists/creds.txt`、`wordlists/jwt.txt` 操作会被后置：须已有本分支旁观者地图，且没有其他未退休、非爆破的 `untried` 方向才放行；命名工具仍后置，不因使用定向文件而提前放行。各副本与接力分支独立使用自己的地图，无情报口令尝试仍应后置。
- HTTP／SSH／FTP 登录尝试并发不超过 4；认证拒绝后等待 0.3–0.5 秒再试下一条；超时或 No route 时暂停整个登录面至少 10 秒。
- 同一登录接口开始口令验证前，先用 2–3 次有界请求核对错误计数、限速与账户锁定语义；发现限制即停止该用户名的口令尝试，禁止多路线同时向同一用户名喷洒口令。
- 多路线共用远端靶机。修改数据库插件、引擎或关键配置前先保留状态与恢复方法，避免破坏其余路线仍在使用的服务。
- 没有明确题目指引时不爆破 JWT／Flask 密钥；已有具体候选时用脚本或 flask-unsign 做有界验证。flask-unsign 的轻量命令不带 wordlist、crack、rockyou 等字典枚举参数，命令内引号参数不超过 24 个；不为验证已知候选调用 jwt_tool／jwt-cracker。后置门禁放行也不代表允许盲猜密钥。
- 内网题先只读枚举、收集证据；修改域、导出凭据等敏感操作前，确认其为获取 flag 所必需，再在授权范围内执行。解题过程可以进行必要的写操作。
- 超时续跑先读交接、已覆盖路径和提交记录，复用已有结果，不从零侦察。实例更换后旧 IP 作废，先确认最新地址和服务指纹；方法与证据可继承，旧连接、会话和运行状态须重新验证，旧实例的阴性结果不能排除新实例。
- 只提交有题目原始材料、靶标响应或可复现推导依据的完整 flag，保留验证证据；不把模型或扫描输出整表当候选，不把占位符、截断片段和猜测混入提交。平台明确拒绝的同一字符串不重复提交；拒绝只否定该字符串，不否定整个方向。
- 以真实应用层协议响应确认服务，外层网关可能对任意端口完成 TCP 握手后断开。有状态或流式协议在同一脚本内保持会话，脚本存入 /workspace 复用。多路线共享靶标时控制合计并发和负载。进入节点后先梳理启动流程、计划任务与配置凭据，再在授权范围内通过主机名解析与系统配置定位内网拓扑，不硬编码动态 IP。
